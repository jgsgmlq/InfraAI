# AI-Native Infrastructure Framework - 最高指令

> 本文件定义项目的核心定位和设计原则，是系统的"宪法"，所有设计决策必须符合这些原则。

---

## 项目定位

**这是一个 AI 工作环境框架**，不是给人类直接使用的 CLI 工具。

### 用户交互模型

```
┌─────────────────────────────────────────────────────────┐
│                      用户（人类）                        │
│                                                         │
│   使用自然语言下达命令，无需了解技术细节                    │
│   例如："帮我创建一个新工具"、"检查一下 SDK"               │
└─────────────────────┬───────────────────────────────────┘
                      │ 自然语言
                      ▼
┌─────────────────────────────────────────────────────────┐
│                     AI（Claude）                         │
│                                                         │
│   1. 理解用户意图                                        │
│   2. 根据 Skills 指导进行编程                            │
│   3. 调用 SDK 工具辅助执行                               │
│   4. 产出代码或执行结果                                  │
└─────────────────────┬───────────────────────────────────┘
                      │ 按 Skills 指导编程 + 调用工具
                      ▼
┌─────────────────────────────────────────────────────────┐
│                   Skills + SDK 工具层                    │
│                                                         │
│   Skills：AI 的编程指南（原则、流程、检查点、约束）        │
│   SDK 工具：辅助执行（审查、生成、检查）                   │
└─────────────────────────────────────────────────────────┘
```

### 三层职责

| 层级 | 接口形式 | 职责 |
|------|----------|------|
| **用户层** | 自然语言 | 表达意图，无需知道命令格式 |
| **AI 层** | Skills | 理解意图 → 按指南编程 → 调用工具 → 返回结果 |
| **工具层** | SDK CLI | 提供稳定、可预测的辅助能力 |

## 核心设计原则

### 1. 用户只说人话

用户无需记忆任何命令，只需用自然语言表达意图：
- "帮我创建一个处理数据的工具"
- "检查一下这个 SDK 是否完整"
- "把框架部署到新项目"

AI 负责理解意图并执行。

### 2. Skills 是 AI 的编程指南

Skills 不是简单的"触发词匹配"，而是 **完整的编程指导**：
- **原则**：遵循什么规范
- **流程**：按什么步骤执行
- **检查点**：哪些需要确认
- **HARD GATES**：必须满足的交付条件
- **恢复策略**：出错了怎么处理

### 3. SDK 工具是辅助手段

工具的作用是 **辅助 AI 完成任务**，而非替代 AI：
- `audit-sdk`：帮助 AI 验证产出是否符合规范
- `create-sdk`：帮助 AI 快速生成骨架代码
- `list-tools`：帮助 AI 了解可用能力

### 4. 框架自我维护

AI 不仅是使用者，也是维护者：
- 能检查工具是否符合规范
- 能审查文档是否过时
- 能发现并修复问题

## 项目范围

### 在范围内（IN SCOPE）

- 框架自身的创建、维护、部署
- 工具/SDK 的创建、审查、管理
- Skills 系统的编写和组织
- 框架到新项目的移植

### 不在范围内（OUT OF SCOPE）

- 通用编程能力（调试、重构等）—— 由 AI 本身提供
- 业务代码编写 —— 由项目特定 Skills 或 AI 通用能力处理
- 外部工具集成 —— 由外部插件（如 superpowers）提供

## 设计决策指南

当面临设计选择时，按以下优先级判断：

### 优先级 1：用户体验

用户能否用自然语言完成任务？
- ✅ 用户说"创建工具" → AI 理解并执行
- ❌ 用户需要记住 `python sdks/infra-core/cli/main.py create-sdk ...`

### 优先级 2：AI 可操作性

AI 能否清晰知道该做什么？
- ✅ Skills 有明确的步骤和检查清单
- ❌ 含糊的"最佳实践"建议

### 优先级 3：Token 效率

能否复用而非重复？
- ✅ 调用现有工具获得稳定输出
- ❌ 每次都让 AI 从头写代码

### 优先级 4：可维护性

框架能否自我检查和修复？
- ✅ 有审查工具自动发现问题
- ❌ 依赖人工检查

## 评估标准

评估系统设计时，使用以下问题：

| 问题 | 正确答案 |
|------|----------|
| 用户需要记住命令吗？ | 不需要，用自然语言 |
| AI 知道该怎么做吗？ | 知道，看 Skills |
| 工具输出可预测吗？ | 可预测，经过测试 |
| 能复用还是要重写？ | 能复用 |
| 能自动检查问题吗？ | 能，有审查工具 |

---

## 禁止事项

1. **禁止要求用户记命令**：用户只需说人话
2. **禁止纯文档输出**：必须产出可执行工具
3. **禁止模糊指导**：Skills 必须有明确步骤和检查点
4. **禁止跳过验证**：交付前必须通过审查工具检查
