## 🎯 コア理念

**ユーザーが自然言語で話す → AIがSkillsに従ってコーディング → ツールが実行を支援**

これはAI支援開発のために設計された作業環境フレームワークです：
- **ユーザー**：自然言語でコマンドを発行、技術的な詳細は不要
- **AI**：Skillsのガイダンスに従ってコーディング、SDKツールを呼び出して支援
- **ツール**：安定した予測可能な機能を提供

## 🏗️ アーキテクチャ

これは2つのレイヤーを持つ**ポータブルIDEプラットフォーム**です：

### 📦 フレームワークレイヤー（安定、気軽に変更しない）
- `sdks/` - SDKツールキット
- `scripts/` - フレームワークツール
- `.claude/` - Claude Code設定
- `docs/` - 仕様ドキュメント
- `core/` - フレームワークコア（ポータブルテンプレート）
- `registry/` - ツールレジストリ

### 💼 プロジェクトレイヤー（ユーザーワークスペース、柔軟な開発）
- ルートにプロジェクトサブディレクトリを作成
- 例：`my-web-app/`、`data-analysis/`
- フレームワークレイヤーのSDKツールを呼び出す
- ビジネスロジックを柔軟に実装

**アーキテクチャの類推**：
- SDKフレームワーク = npmパッケージライブラリ（再利用可能なツールを提供）
- ユーザープロジェクト = npmパッケージを使用するアプリ（ツールを呼び出し、ツールのソースは変更しない）

## 🚀 クイックスタート

### 1. 依存関係のインストール

```bash
pip install -r requirements.txt
```

### 2. プロジェクトの初期化

Claude Codeで実行：

```
/init
```

または手動で実行：

```bash
python scripts/list_tools.py    # 利用可能なツールを表示
python scripts/list_skills.py   # 利用可能なスキルを表示
python scripts/audit_all.py     # ヘルスチェック
```

### 3. 最初のプロジェクトを作成

AIに自然言語で伝える：

```
"Webアプリケーションを作成してください"
"データ分析プロジェクトを作成"
"ユーザーログイン機能を実装"
```

AIは自動的に：
1. プロジェクト名を尋ねる
2. ルートにプロジェクトサブディレクトリを作成
3. プロジェクトディレクトリでプロジェクトをセットアップ
4. SDKツールを呼び出して支援

## 🎯 作業モード

### 🟢 プロジェクト開発モード（デフォルト）

AIはデフォルトでこのモードで、プロジェクトサブディレクトリで作業：

```
"新しいプロジェクトを作成"
"ユーザーログイン機能を実装"
"データ検証を追加"
"このバグを修正"
```

### 🔧 SDK開発モード（明示的なトリガー）

明示的に述べられた場合のみこのモードに入る：

```
"infra-core SDKを変更"
"新しいSDKツールを作成"
"フレームワーク機能を拡張"
```

## 🛠️ コア原則

### 1. SDK安定性原則

- **フレームワークレイヤーは安定**：SDKツールキットは気軽に変更しない
- **プロジェクトレイヤーは柔軟**：ユーザープロジェクトは自由に開発可能
- **新機能はまずプロジェクトで実装**：検証後にSDKへの移行を検討

### 2. 作業モード認識

- **デフォルトはプロジェクト開発モード**：AIはプロジェクトサブディレクトリで作業
- **SDK開発モードは明示的なトリガー**：明示的に述べられた場合のみフレームワークレイヤーを変更
- **不確実な場合はユーザーに尋ねる**：AIはまずユーザーの意図を確認

### 3. リクエスト → ツール → 統合

- すべてのリクエストは実行可能なツールを生成すべき
- ツールを作成せずにドキュメントのみを出力することは許可されない
- ツールは`--help`をサポートし、エラーはstderrに出力

## 💡 使用例

### 新規プロジェクトの作成

```
ユーザー: "Webアプリケーションを作成してください"

AI: "承知しました。プロジェクト名は何ですか？"

ユーザー: "my-web-app"

AI:
1. プロジェクトディレクトリを作成：mkdir my-web-app
2. プロジェクトディレクトリに切り替え：cd my-web-app
3. プロジェクトでWebアプリケーションをセットアップ
4. SDKツールを呼び出す（必要に応じて）
```

### 機能の実装

```
ユーザー: "ユーザーログイン機能を実装"

AI:
1. 既存のSDK機能を確認
2. プロジェクトでログイン機能を実装
3. SDKツールを呼び出して支援
4. フレームワークレイヤーファイルは変更しない
```

### SDKの変更（明示的なトリガー）

```
ユーザー: "infra-core SDKを変更し、新しい監査機能を追加"

AI:
1. 明示的なSDK変更コマンドを認識
2. SDK開発モードに入る
3. sdks/infra-core/api/audit.pyを変更
4. 関連するテストとドキュメントを更新
5. audit-sdkを実行して検証
```

## 🎓 ベストプラクティス

### ユーザー向け

1. **プロジェクト作成時**：「XXXプロジェクトを作成」と言う
2. **機能開発時**：「XXX機能を実装」と言う
3. **フレームワーク変更時**：「SDKを変更」または「フレームワークを拡張」と明示的に言う
4. **不確実な場合**：自然言語で意図を表現、AIがガイド

### AI向け

1. **デフォルトはプロジェクト開発モード**：プロジェクトサブディレクトリで作業
2. **SDKツールを優先**：再実装ではなく
3. **成熟後に移行について尋ねる**：許可なくプロジェクトコードをSDKに移行しない
4. **不確実な場合はユーザーに尋ねる**：推測ではなく

## 🤝 コントリビューション

### 新しいツールの追加

1. プロジェクトで実装と検証
2. 成熟後、SDKへの移行を検討
3. `docs/60_sdk_specification.md`仕様に従う
4. `audit-sdk`を実行して検証

### 新しいSDKの作成

1. SDKパッケージ仕様に従う
2. API、CLI、Skills、Testsを含む
3. manifest.yamlを更新
4. 対応するエントリスキルを作成
