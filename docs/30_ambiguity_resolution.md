# Ambiguity Resolution Guide

本文档定义了 AI 处理模糊请求的标准流程。

## 核心原则

1. **不假设**：宁可多问一句，也不要擅自决定
2. **先列后选**：展示现有选项，让用户选择
3. **渐进澄清**：从大方向到具体细节，逐步确认

---

## 识别模糊请求

### 类型 1：目标不明确

```
用户: "帮我优化一下"
问题: 优化什么？性能？代码质量？可读性？
```

**处理方式**：
1. 列出可能的优化方向
2. 询问用户具体目标
3. 确认后再行动

### 类型 2：范围不明确

```
用户: "改一下那个工具"
问题: 哪个工具？改什么部分？
```

**处理方式**：
1. 运行 `python scripts/list_tools.py` 列出所有工具
2. 询问具体是哪个工具
3. 确认要修改的内容

### 类型 3：方案不明确

```
用户: "帮我做个数据处理的脚本"
问题: 处理什么数据？输入输出是什么？
```

**处理方式**：
1. 询问数据来源和格式
2. 询问期望的输出
3. 确认边界情况处理

---

## 标准澄清流程

```
收到模糊请求
    ↓
识别模糊类型
    ↓
┌─ 目标不明确
│   → "您希望达成什么目标？以下是几个可能的方向：..."
│
├─ 范围不明确
│   → "请确认您指的是以下哪个？..."
│   → 使用工具列表辅助确认
│
└─ 方案不明确
    → "在开始之前，我需要确认几个细节：
       1. 输入是什么？
       2. 期望的输出是什么？
       3. 有什么特殊要求？"
```

## 澄清问题模板

### 新建工具

```markdown
在开始创建工具之前，请确认以下信息：

1. **工具名称**: 您希望这个工具叫什么？（例如：process-data）
2. **功能描述**: 这个工具做什么？
3. **输入**: 接受什么参数/文件？
4. **输出**: 产生什么结果？输出到 stdout 还是文件？
5. **错误处理**: 遇到错误时应该怎么做？
```

### 修改工具

```markdown
您提到要修改工具，请确认：

1. **目标工具**: 是 `<tool-id>` 这个工具吗？
2. **修改内容**: 具体要改什么？
   - [ ] 添加新功能
   - [ ] 修复 bug
   - [ ] 改变现有行为
3. **向后兼容**: 需要保持现有用法不变吗？
```

### 查找/搜索

```markdown
您提到要查找，请确认：

1. **查找什么**: 文件名？代码内容？工具？
2. **范围**: 整个项目？特定目录？
3. **用途**: 找到后要做什么？
```

## 可以假设的情况

以下情况可以合理假设，不必每次都问：

| 场景 | 可假设的默认值 |
|------|---------------|
| 新工具的退出码 | 0/2/3 标准码 |
| 输出格式 | Markdown（除非用户指定） |
| 注册表位置 | `registry/tools.yaml` |
| Skill 文档位置 | `.agent/skills/<id>.md` |
| 编码 | UTF-8 |

---

## 必须确认的情况

以下情况 MUST 与用户确认，不能假设：

| 场景 | 原因 |
|------|------|
| 工具名称和 ID | 影响文件命名和注册 |
| CLI 参数设计 | 影响用户使用方式 |
| 破坏性操作 | 可能造成数据丢失 |
| 修改现有工具 | 可能影响其他功能 |
| 依赖新库 | 可能影响可移植性 |

## 示例对话

### 好的处理方式

```
用户: 帮我写个工具

AI: 好的，在开始之前，我需要确认几个细节：
    1. 这个工具要做什么？
    2. 您希望它叫什么名字（例如：my-tool）？
    3. 需要什么输入参数？

用户: 处理 CSV 文件，叫 csv-parser，输入是文件路径

AI: 明白了。让我确认一下：
    - 工具 ID: csv-parser
    - 脚本: scripts/csv_parser.py
    - 输入: --input <文件路径>
    - 输出: 处理结果输出到 stdout

    这样理解对吗？确认后我开始实现。
```

### 不好的处理方式

```
用户: 帮我写个工具

AI: [直接开始写一个名为 generic_tool.py 的脚本...]

问题: 没有确认需求就开始实现
```
