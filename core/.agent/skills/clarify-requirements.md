# Clarify Requirements

## Purpose

当用户需求不明确时，通过提问引导用户整理和明确需求。

## When to Use

- 用户表达的需求比较模糊
- 需要在开始实现前确认细节
- 用户说"我有个想法"但不确定具体要什么

## Trigger Phrases

When the user says:
- "我有个想法..."
- "我想做一个..."
- "帮我想想怎么..."
- "I have an idea..."
- "I want to build..."

## Process

### Step 1: 确认目标

问用户：**"你想解决什么问题？"** 或 **"这个功能要达到什么效果？"**

### Step 2: 确认范围

问用户：**"需要实现哪些具体功能？"** 列出 2-4 个核心功能点。

### Step 3: 确认约束

问用户：**"有哪些限制条件？"** 例如：
- 技术栈限制
- 时间限制
- 兼容性要求

### Step 4: 输出需求摘要

整理为结构化的需求摘要：

```
📋 需求摘要

目标：[一句话描述]

功能点：
1. [功能 1]
2. [功能 2]
3. [功能 3]

约束：
- [约束 1]
- [约束 2]

确认以上理解是否正确？
```

## When to Escalate to superpowers:brainstorming

当出现以下情况时，建议用户使用 superpowers:brainstorming：

- 需要探索多种技术方案
- 需要权衡不同架构的取舍
- 需求复杂，涉及多个系统或模块
- 用户不确定最佳实现方式

**告知用户**："这个需求比较复杂，建议我们用 brainstorming 来深入分析，我会调用 superpowers 插件来帮助。"

## Principles

1. **一次一个问题**：不要同时问多个问题
2. **简单优先**：能 3 个问题内明确的需求，就不要问更多
3. **确认理解**：在开始实现前，确保用户认可需求摘要
